# Architecture

```
┌──────────── Android ────────────┐        ┌───────────── macOS ─────────────┐
│ React Native UI (TypeScript)    │        │ SwiftUI (MenuBarExtra + window)  │
│   android/App.tsx, android/src  │        │   macos/CrossDrop/               │
│        │ JSON snapshots / cmds  │        │        │                         │
│ TurboModule (Kotlin)            │        │ App model / services             │
│   bridge/CrossDropModule        │        │                                  │
│ Engine (Kotlin): NSD, service,  │        │ Bonjour (NWListener/NWBrowser)   │
│   MediaStore, Keystore, history │        │ Keychain, history, notifications │
│        │                        │        │        │                         │
│ core (pure Kotlin/JVM)  ◄──── protocol v1 ────►  CrossDropCore (Swift)       │
│   android/core                  │  TCP   │   macos/Sources/CrossDropCore    │
└─────────────────────────────────┘        └──────────────────────────────────┘
```

## Principles

* **One protocol, two independent implementations.** `docs/protocol-v1.md` is the
  contract. `protocol/test-vectors/v1.json` (generated by a Python reference)
  is checked by both the Kotlin and Swift unit tests. CI also runs real transfers
  Kotlin→Swift and Swift→Kotlin over TCP (`integration-tests/interop.sh`).
* **File bytes never cross the JS bridge.** The React Native layer only sees
  content URIs and state snapshots. Hashing, encryption and streaming happen in
  Kotlin with 256 KiB buffers.
* **Bounded memory and backpressure.** Each connection has one reader thread that
  feeds a 4-record queue; when the consumer is slow, reading stops and TCP flow
  control slows the sender. Senders hash files before offering (so the offer
  carries the SHA-256) and stream again for sending.
* **Battery.** Discovery runs only while a screen that needs it is visible.
  Receiving runs only while switched on (Android turns it off after 10 idle
  minutes) and keeps a foreground service only for that time or while a transfer
  runs. No polling.

## Repository layout

| Path | What |
|---|---|
| `docs/` | Protocol, security model, testing matrix, release process |
| `protocol/test-vectors/` | Shared vectors and their Python generator |
| `android/` | React Native project root (package.json, TypeScript UI) |
| `android/android/` | Gradle project for the Android app (Kotlin native code) |
| `android/core/` | Protocol engine, pure Kotlin/JVM, plus the `crossdrop-cli` test tool |
| `android/specs/` | TurboModule spec (codegen input) |
| `macos/` | Swift package (`CrossDropCore`, `crossdrop-cli`, tests) and the SwiftUI app (`CrossDrop/`, built with XcodeGen from `project.yml`) |
| `integration-tests/` | Cross-implementation tests |
| `scripts/` | Icon rendering, DMG packaging, local checks |

The brief suggested `android/app/...` directly. React Native needs its JS
project root (package.json, node_modules) one level above the Gradle project,
so the Gradle project lives in `android/android/`. The pure Kotlin protocol
code is a separate Gradle build (`android/core`) included into the app as a
composite build, so it can be tested and run on any JVM, including the macOS CI
runner for interop tests.

## Android components (`android/android/app/src/main/java/com/crossdrop/`)

| Package | Responsibility |
|---|---|
| `bridge/` | TurboModule: commands from JS, `CrossDropState` snapshot events |
| `engine/` | State, transfers, prompts, snapshot JSON |
| `discovery/` | NSD browse/resolve and service registration |
| `identity/` | Android Keystore identity key |
| `storage/` | MediaStore writer (pending → verified → published), trust store, history, prefs |
| `service/` | `connectedDevice` foreground service while receiving or transferring |
| `share/` | Share sheet intents and picker results → file metadata |
| `notifications/` | Channels; lock-screen-safe notifications |
| `tiles/` | Optional Quick Settings tile |

## Visual design

Both apps use the same "liquid glass over a wallpaper" language:

* **Wallpapers** are original artwork rendered by `scripts/make_wallpapers.py`
  (Dusk, Lagoon, Canopy, Midnight). No stock photos, so no licence questions.
  Android "Auto" follows the system appearance (Lagoon in light, Dusk in dark).
* **Frosted glass on Android** (`android/src/components/Frost.tsx`): React Native
  has no cross-version backdrop blur, so each glass surface draws a small
  pre-blurred copy of the wallpaper positioned exactly where the real wallpaper
  sits behind it (and follows scrolling via an Animated scroll offset), then a
  tint, a top sheen and a rim-lit hairline border. It looks like a live backdrop
  blur, costs one extra image draw per surface and works on every Android version.
* **Frosted glass on macOS**: the same aligned-blur technique in SwiftUI; on
  macOS 26 built with Xcode 26 the system `.glassEffect` is used instead.
* **Type**: Poppins on Android (bundled under the SIL Open Font License, see
  `android/android/app/src/main/assets/fonts/OFL.txt`), SF Pro on macOS.
* The DMG opens as a styled installer window (`scripts/make_dmg_background.py`,
  `scripts/build-dmg.sh`).
